——— 2. Primary Data Model (DB) ———

• close_sessions (065_tenant_close_sessions.sql): id, tenant_id, entity_id, period_start, period_end, basis, standard, status (draft|in_progress|ready_for_review|finalized|locked|certified), created_at, updated_at. No overlapping (tenant_id, entity_id, daterange) via EXCLUDE. 078: certified_by, certified_at, certification_memo; 085: certified_snapshot_id (links to ledger_snapshots).
• period_trial_balance (060_period_trial_balance.sql): tenant_id, period_label (PK), source (uploaded|synced), entries JSONB, uploaded_at, uploaded_by, synced_at, file_name, connection_id, created_at, updated_at.
• tenant_hitl_staging (062_tenant_hitl_staging_and_supervisor_sessions.sql): id, tenant_id, proposed_action, justification, status (pending|approved|rejected), type (journal_entry|policy_change|adjustment|flag_override|other), amount, payload JSONB, created_at, updated_at, approved_at, approved_by, rejected_at, rejected_reason.
• journal_entries (072_tenant_journal_entries.sql): id, close_session_id, tenant_id, status (draft|proposed|approved|posted|exported|rejected), memo, source (manual|suggestion|recon|accrual), created_by, approved_by, posted_at, reversal_date, created_at, updated_at. journal_entry_lines: je_id, line_index (PK with je_id), account_ref, debit, credit, description; 084_journal_entry_lines_amount_provenance.sql adds amount_provenance JSONB (comment: ledger_exact | engine_calculation | human_entered).
• audit_ledger (051_audit_ledger.sql): id, tenant_id, period_label, event_type, deterministic_flag_snapshot JSONB, agent_dissent_snapshot JSONB, user_prompt_rationale, previous_entry_hash, entry_hash, created_at, created_by. 079: hash_version SMALLINT (1=raw legacy, 2=canonical).
• ledger_snapshots (083_ledger_snapshots.sql): id UUID, tenant_id, period_label, created_at, created_by, source (precheck|close_session|import), snapshot_payload_json JSONB, snapshot_hash TEXT, hash_version INTEGER, close_session_id. Indexes on tenant_id, (tenant_id, period_label), close_session_id, (tenant_id, snapshot_hash).
• period_locks (003_tenant_schema.sql): tenant_id, period_label (PK), locked_at, locked_by, reason.
• close_checklist_items (073_tenant_close_checklist_items.sql): id, close_session_id, code, name, status (pending|in_progress|completed|skipped), required, completed_by, completed_at, notes, created_at, updated_at.

——— 3. Core End-to-End Flows ———

TB ingest / parse / staging
• Endpoints: POST /api/trial-balance/ingest (or /api-dev/trial-balance/ingest when NODE_ENV !== production). Handler: src/routes/trial-balance/ingest.ts (router post /ingest).
• Services: ingestTrialBalanceFile (fileIngestion), parseTrialBalance (trialBalanceParser), buildValidatedStatements (financialStatements), runClassifier/runAdvisor (ai_orchestrator), shouldEscalateToHuman/submitToStaging (hitl_orchestrator), createStagingItem/updateStagingPayload (persistence_service). DB: tenant_hitl_staging (createStagingItem), period_trial_balance (only after resolve; ingest path that is imbalanced does not write period_trial_balance).
• Gating: assertPeriodNotLocked (period_lock_service) before writing; MathematicalIntegrityError → 422; when imbalanced, staged only and 200 with status 'staged' and imbalanceAmount (no write to period_trial_balance).

HITL resolve-ingest
• Endpoint: POST /api/hitl/resolve-ingest. Handler: src/routes/hitl.ts (path /resolve-ingest). Service: resolve-ingest logic in hitl route using adjustment lines; re-verify math; save to period_trial_balance (via runResultPipeline / persistence and trial balance store). Gating: tenant/pool required; adjustment must balance (debits = credits).

JE create + post (including provenance)
• Endpoints: POST /api/close/journal-entries (create), POST /api/close/journal-entries/:id/propose, POST /api/close/journal-entries/:id/approve, POST /api/close/journal-entries/:id/post. Handlers: src/routes/close/close_journal_entries.ts. Service: src/services/journal_entry_service.ts (createJE, propose, approve, post); repository: src/db/repositories/journal_entry_repository.ts. DB writes: journal_entries, journal_entry_lines (with amount_provenance when provided). Provenance: validateJEProvenance (src/types/amount_provenance.ts) called from journal_entry_service — non-zero amounts require valid amountProvenance (ledger_exact | engine_calculation | human_entered).

Precheck “board-ready”
• Endpoint: POST /api/precheck/board-ready. Handler: src/routes/precheck.ts. Service: runPrecheckBoardReady (src/services/precheck_board_ready_service.ts). No DB writes; uses finalIntegrityCheck and runIntegrityGate + detectSuspiciousPlugs from integrity_check and integrity_gate_service. Query: ?format=json|text.

Close session lock + certify
• Lock: POST /api/close/period-lock. Handler: src/routes/close/close_period.ts. Service: lockPeriod (period_lock_service.ts) → period_lock_repository.lockPeriod. DB: period_locks (INSERT/ON CONFLICT UPDATE). Certify: POST /api/close/sessions/:id/certify. Handler: src/routes/close/close_sessions.ts. Service: certifyCloseSession (close_session_service.ts). Gating: session must exist and status === 'locked'; computeReadiness (close_checklist_readiness_service) must have no hardBlockers; canPerform(actorRole, 'certify_close'). DB: getAdjustedTrialBalance → build snapshot payload → createSnapshotFromTrialBalanceAndEntries → insertLedgerSnapshot; repo.updateCertification (close_session_repository) sets status certified, certified_by, certified_at, certification_memo, certified_snapshot_id.

Snapshot creation + hashing + verification
• Creation: createSnapshotFromTrialBalanceAndEntries (ledger_snapshot_service.ts) → buildSnapshotPayloadFromInput → hashSnapshotPayload (lib/snapshot_hash.ts) → insertLedgerSnapshot (ledger_snapshot_repository.ts). Verification: verifySnapshotHash (ledger_snapshot_service) recomputes hash from stored payload and compares to snapshot_hash; supports current hash_version and legacy. Certify flow calls createSnapshotFromTrialBalanceAndEntries and then updateCertification with snapshot.id.

Binder generation
• Endpoints: GET /api/audit/binder, GET /api/audit/binder/export/pdf, GET /api/audit/binder/export/csv. Handlers: src/routes/audit/audit_binder.ts. Service: getCertifiedStatementsForBinder (audit_export_service.ts) → buildCertifiedStatementsFromSnapshot or legacy getLastStatementGeneration + finalIntegrityCheck. Gating: closeSessionId required; session.status === 'certified'; checkExportGate (export_gate_service) must allow; when no certified snapshot and legacy not allowed → 422 NO_CERTIFIED_SOURCE. Response headers on success: X-Certified-Source, X-Certified-Snapshot-Id, X-Certified-Snapshot-Hash, X-Certified-Snapshot-Hash-Version.

Certified export (PDF/CSV)
• Endpoints: POST /api/export/pdf (body exportMode: 'certified', closeSessionId), POST /api/export/csv (exportMode: 'certified', closeSessionId). Handlers: src/routes/export.ts. Services: getCertifiedStatementsForBinder (audit_export_service), statementsToExportPayload (certified_statements_service), createPdfFromStructuredPayload (pdf_export), generateCsvWithConfidence (export_service). Gating: closeSessionId required for certified; session must be certified (403 CLOSE_NOT_CERTIFIED otherwise); checkExportGate; finalIntegrityCheck on ledger totals; when no certified source and legacy not allowed → 422 with allowLegacyCertifiedSourceEffective and attemptedSource in body. Success: same trust token headers as binder.

Legacy fallback behavior + flags
• allowLegacyCertifiedSource(req): req.query.allowLegacyCertifiedSource === '1' || process.env.ALLOW_LEGACY_CERTIFIED_SOURCE === 'true' (audit_binder.ts, export.ts, close_sessions certified-source). ALLOW_LEGACY_CERTIFIED_SOURCE() in src/lib/env.ts reads process.env.ALLOW_LEGACY_CERTIFIED_SOURCE === 'true'. getCertifiedStatementsForBinder (audit_export_service) uses options.allowLegacyCertifiedSource === true || ALLOW_LEGACY_CERTIFIED_SOURCE(); when true, falls back to getLastStatementGeneration + finalIntegrityCheck for legacy source; when false and no snapshot, returns null (422 from routes).

——— 4. Deterministic Invariants & Gates ———

• Debits == credits: runIntegrityGate (integrity_gate_service.ts) computes trialBalanceBalances via absGt(totalDebits, totalCredits, tolerance); getToleranceForGate from shared/config financial_rules (roundingTolerance or materiality). assertIntegrityGateOrThrow throws MathematicalIntegrityError on failure.
• Assets == Liabilities + Equity (tolerance): same runIntegrityGate; balanceSheetBalances via absGt(totalAssets, rhs, tolerance).
• Plug detection: detectSuspiciousPlugs (integrity_gate_service) — accounts matching PLUG_ACCOUNT_PATTERN (Miscellaneous|Suspense|Other); threshold (e.g. 0.9) of total net activity in plug accounts → isSuspicious. finalIntegrityCheck (integrity_check.ts) calls runIntegrityGate and optionally detectSuspiciousPlugs; if plugSuspicious returns passed: false.
• Period lock enforcement: assertPeriodNotLocked (period_lock_service) throws PeriodLockedError if isPeriodLocked; used in trial-balance ingest (ingest.ts), parser (parser.ts), close_closing_entries, close_adjustment_update_service, protocol_bridge. isPeriodLocked checks period_lock_repository (DB) or in-memory fallback when no pool.
• Truth gate / final integrity check: finalIntegrityCheck (integrity_check.ts) runs runIntegrityGate (integrity_gate_service) and optionally plug detection; used before export in export.ts, certified_statements_service, audit_export_service, precheck_board_ready_service.
• Audit ledger chain verification: verifyChain (audit_ledger_service.ts) delegates to auditLedgerRepo.verifyChain (audit_ledger_repository.ts): loads entries by tenant_id ORDER BY created_at; verifies each computed hash === row.entry_hash and row.previous_entry_hash === prevHash. checkExportGate (export_gate_service) calls verifyChain; if !valid returns allowed: false, alert CRITICAL_TAMPER_ALERT.

——— 5. Snapshot Determinism Hardening ———

• Canonical serializer: src/lib/canonical_json.ts — canonicalStringifyKeysOnly (deep key sort, omit undefined, arrays preserved in order); canonicalStringifyLegacy (key sort + array sort by canonical string). Snapshot hashing uses keys-only after domain-aware sort (snapshot_hash.ts).
• Snapshot hash: hashSnapshotPayload (src/lib/snapshot_hash.ts): buildHashInput adds hash_version ('v1'), normalizePayloadForHash sorts trialBalance.entries and entries by entrySortKey (accountName, debit, credit, lineId, accountCode, description, amountProvenance); validateHashInput allows hash_version; canonicalStringifyKeysOnly(hashInput) then SHA-256 hex. Excluded from hash: id, createdAt, DB-generated fields; only hash_version, trialBalance, entries (optional) in hash input.
• Explicit ordering: entrySortKey (snapshot_hash.ts) returns concatenation of accountName, debit, credit, lineId, accountCode, description, canonicalStringifyLegacy(amountProvenance) joined by \0. normalizePayloadForHash sorts entries by entrySortKey(a).localeCompare(entrySortKey(b)).
• hash_version: getHashVersionForStorage() (snapshot_hash.ts); stored in ledger_snapshots.hash_version. verifySnapshotHash returns false if snapshot.hashVersion !== getHashVersionForStorage().
• Reproducibility integration test: tests/integration/snapshot_reproducibility.test.ts — ingest TB, create session, lock, certify; get snapshot from DB; rebuild adjusted state via getAdjustedTrialBalance + buildSnapshotPayloadFromInput; recompute hash via hashSnapshotPayload; assert recomputed === stored snapshot_hash.
• Drift protection: SNAPSHOT_PAYLOAD_ALLOWED_TOP_LEVEL_KEYS and SNAPSHOT_PAYLOAD_REQUIRED_TOP_LEVEL_KEYS (ledger_snapshot_service.ts) restrict payload to trialBalance (required) and entries (optional). HASH_INPUT_ALLOWED_TOP_LEVEL_KEYS and HASH_INPUT_REQUIRED_TOP_LEVEL_KEYS (snapshot_hash.ts) restrict hash input to hash_version, trialBalance, entries. Unit tests: tests/unit/ledger_snapshot_hash.test.ts — describe('snapshot payload structure (drift protection)') asserts payload and hash input have only allowed top-level keys; no periodLabel etc. in payload.
